## 3. The model (binding)

### 3.1 The field (contract with PSW)

- Name `sashProportion`. Values: `standard`, `cottage-40-60`, `cottage-1-3`. Missing, null or empty means `standard`.
- Read it in `normaliseToWindowSpec()` (`src/engine/specification.js`) the way `splitRatio` is read: `item?.sashProportion || fc.sashProportion || 'standard'`, into `windowSpec.sash.proportion`.
- Store it on the window record in `projectStore.js` next to `splitRatio` (both window builders, add and update), and carry it through `windowSpecToConfig.js`, the configurator state and every place `splitRatio` travels today. Grep `splitRatio` and follow every hit.
- An unknown value is an explicit error for that window, raised the way `ArchError` reports an unknown arch pattern. Never a silent fallback to standard.

### 3.2 The formula

One shared exported helper in `src/engine/calculations.js`, used by every caller (no second copy of the formula anywhere):

```
sashHeightsFor(frameHeight, proportion)
  total  = totalSashHeightFor(frameHeight)            // frame H - profile deductions.sashHeight + meeting rail face (default H - 92)
  standard:       top = (total - diff) / 2, bottom = top + diff   // diff = sashFaces().diff (default 90 - 57 = 33): today's rule, unchanged
  cottage-40-60:  top = total * 0.4,        bottom = total - top
  cottage-1-3:    top = total / 3,          bottom = total - top
  returns { total, top, bottom }
```

No rounding inside the engine (today's displays keep their own rounding).

### 3.3 Reference numbers (default profile: sashHeight deduction 135, meeting rail 43, top rail 57, bottom rail 90, glass rebate 11.5)

Glass unit heights follow the existing rule in `lists.js`: upper = top - (57 + 43 - 23), lower = bottom - (43 + 90 - 23).

### 3.4 Rules

- Allowed on `sash.type` `double` and `triple`. Triple: the centre sashes and both side FIX lights use the same top and bottom heights (one meeting rail line), as they do today.
- Glazing arch head (`headType 'arch'`) is allowed with cottage. An arched window (`windowSpec.arch.shape` set) with a cottage value is an explicit error (3.1 mechanism).
- Minimum frame height 900 for cottage: the configurator disables the cottage choices below 900. The engine still computes a stored cottage window below 900 (it exists, it is not wrong), and the window detail page shows a warning line.
- Price: `DEFAULT_PRICING.cottageSash = 0.05` next to `archedHead`. In `calculatePrice()` (sash branch) add `subtotal += subtotal * pricing.cottageSash` for a cottage value, right after the `archedHead` line and before the colour surcharge. Breakdown field `cottageSurcharge`. Nothing else in pricing changes.
- 3D meeting line, for EVERY sash window (standard included, owner approved 09.10.2026): the 3D keeps its own frame geometry and places the meeting line at the same fraction of the opening as production: `f = (bottom - meet / 2) / (total - meet)` measured from the bottom of the opening (`meetingY = lowerVisibleBottomY + availableHeight * f`), with `f` coming from the shared helper through the 3D config, not computed in the component. Today `f = 0.5`; standard at H 1400 becomes 0.5130, cottage-40-60 0.6034, cottage-1-3 0.6723. Opening limits become two: the lower sash can rise by (upper part - 120), the upper sash can drop by (lower part - 120), using the same 120 margin as today.
